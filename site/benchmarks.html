PROTOCOL

Controlled physical evaluation

Abstract

Physical robot tests can change before a policy takes its first action. Object pose, clutter, lighting, and reset quality all affect the task. An aggregate score can hide those differences. Prism pairs a defined test condition with projected setup guidance and a vision check, then compares policies across matched cases with completion criteria set in advance.

This workspace demonstrates the reporting format. It does not report a completed study. Provider names and marks identify an example lineup and do not imply participation or endorsement.

Evaluation protocol

  1. Define the caseRecord the task, objects, poses, exact policy version, and completion rubric.
  2. Stage and verifyProject placement guidance. Verify initial conditions against declared tolerances before accepting a rollout.
  3. Run a matched comparisonUse the same cases and action budgets, resetting the scene between attempts.
  4. Score and retain evidenceKeep setup rejection separate from task failure. Preserve video, outcome, and scoring rationale.
  5. Change one variableSweep position, orientation, clutter, object identity, or lighting while holding the other conditions fixed.

Metrics and ranking

Completion
Completed trials divided by valid attempts. The aggregate sums counts, not rounded percentages.
Rank
Descending completion rate for the selected task. Equal rates share the same rank.
95% interval
Wilson binomial interval using the displayed sample counts. No claim of statistical superiority is made; repeated or correlated trials require further analysis.
Missing evidence
Missing model versions, setup records, and recordings remain marked as unavailable. They are never treated as verified.
