03 · What Prism does

The test starts
before the robot moves.

Test code can name a position. It can't make anyone put the cup there. Prism closes that gap: it projects the setup onto the table, checks it with cameras, and ties every result to the exact scene that produced it.

  1. 01

    Define the case.

    Placements come from the lab's own code through our SDK, or Prism generates a set for the task.

  2. 02

    Project, place, verify.

    The setup appears on the table. Cameras confirm identity, pose and tolerance before anything runs.

  3. 03

    Run the robot.

    Any arm, any policy. Every model faces the same verified starting conditions.

  4. 04

    Keep the evidence.

    Outcome, model version and verified setup are stored together, so a result can be trusted, compared and replayed.

05 · The data opportunity

Find a failure once.
Use it forever.

A single success rate hides everything useful. Because Prism verifies every starting condition, each trial becomes a case a lab can run again: on another station, after the next update, in another building. That library of real-world cases is the asset, and it compounds with every run. Over time it becomes the benchmark the whole industry reports against: the ImageNet of physical AI.
