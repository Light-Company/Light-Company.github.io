# Build with initiative

This repository is The Light Company's public website. Take generous ownership of a requested outcome. Explore, propose, implement, test and finish. Make useful reversible decisions without asking the owner to become a project manager. The owner prefers a complete, reviewable result over a list of things someone could build.

## Freedom to do good work
- Work on a focused branch from current remote main. Read tasks/lessons.md and PRODUCT.md first.
- Use judgment on copy, composition, information architecture and implementation. Explain consequential assumptions in the handoff; do not stop for routine taste decisions.
- Make ambitious concepts tangible. A clearly labeled concept may be rich and speculative. Keep that label in the visible experience, metadata and machine-readable documentation.
- Research primary sources, follow useful skills, and improve the actual visitor journey rather than adding ceremonial documents.
- Use plain language. Here, poetry comes from physical things: light on a table, a cup moved, a scene remembered. Technical depth belongs where readers choose it.

## Truth and authority
Creative freedom is not permission to invent customers, results, job openings, certifications, pricing or shipped features. Separate observed behavior, company-described workflow and proposed direction. Never treat a success animation as proof of persistence. Do not expose private lab records, credentials or personal information. Product robots are outside this website's operating authority.

Publication follows the user's authorization in the active task. Do not add an extra approval ritual when they have already asked to publish. Never infer permission to send outreach, spend money, alter account access or accept a contract from a website request.

## Implementation and checks
- New editorial pages live in lib/company-content.mjs and render through lib/company-site.mjs. scripts/build-company.mjs produces route files, static HTML, sitemap and AI-readable documentation.
- Run npm test and node scripts/prune-deployment-media.mjs for a release. Review changed UI in the browser at desktop and phone sizes, including navigation and meaningful controls. Preserve reduced motion and keyboard access.
- Keep raw recordings out of release archives. The media pruner retains runtime references, including dynamic gallery GIFs. Source originals stay in the full GitHub checkout.
- Keep the GitHub merge and Sites release tied to the same reviewed source. Preserve .openai/hosting.json project identity and public audience in the hosting checkout. Never write hosting credentials to files or logs.
- Record remaining uncertainty specifically. A local preview, a successful hosted deployment and a verified physical experiment are different kinds of evidence.

## Finish
Ship the requested result, explain what changed and what was checked, and provide the usable link. Leave durable context for the next contributor. Be bold with craft, careful with facts, and generous with the reader's attention.
